# 《万物造化》分阶段实现路线

> **文档定位**：本文件把游戏从完整愿景拆成可开发、可测试、可验收的阶段。阶段划分以“先验证核心乐趣，再扩展内容规模”为原则，避免一开始同时推进大世界、长剧情、复杂数值和完整美术。

---

## 一、总体拆分原则

本项目的核心不是先做完全部玄黄大宇宙，而是先验证一个问题：

> 玩家是否愿意在探索中发现规则，并在背包 / 法则网格中重新组合规则，再通过自动战斗看到结果。

因此开发顺序必须围绕四个层级推进：

1. **核心手感层**：拖拽物品、触发规则、看到战斗反馈。
2. **短循环层**：一次 5-10 分钟探索能获得新规则、调整 Build、完成战斗。
3. **30 分钟闭环层**：一次内容单元能完成目标、遭遇打压、调整构筑、获得成长、留下新钩子。
4. **章节与世界层**：地点、伙伴、阵营、主线真相和多结局逐步扩展。

每个阶段都需要保留可运行版本。不能只交付静态界面、孤立关卡或只存在文档里的系统。

## 三、P0：预制作冻结

### 阶段目标

把项目从“宏大设定”收束为第一批可实现功能。P0 不追求可玩内容，追求团队对实现范围达成一致。

### 必须产出

| 类型 | 产出物 | 说明 |
| :--- | :--- | :--- |
| 设计 | MVP 功能清单 | 明确第一版只做序章 + 第一章前半。 |
| 设计 | 首批规则表 | 至少 12 条基础规则，覆盖触发、条件、转化、连接和代价。 |
| 设计 | 首批道具表 | 20-30 件道具，包含剑、符、丹、材料、阵盘。 |
| 设计 | 首批敌人表 | 5-8 种普通敌人，2 个精英，1 个首领。 |
| 技术 | Godot 目录和场景规范 | 明确 `scenes/`、`scripts/`、`data/` 的拆分方式。 |
| 技术 | 数据格式草案 | 道具、规则、敌人、关卡、剧情节点优先数据驱动。 |
| 美术 | 灰盒资源规范 | 先使用临时图形和清晰 UI 标识，不等待完整美术。 |

### 暂不实现

- 完整四层宇宙。
- 大量境界、数值膨胀和复杂经济。
- 联网、账号、排行榜、公会和交易。
- 完整配音、过场动画和高规格特效。
- 多结局和周目系统。

### 验收标准

- 能用一页表说清楚第一版有哪些场景、道具、规则和敌人。
- 程序能按照数据表开始搭建原型，不需要等待完整剧情。
- 策划能新增一条规则或一个道具，并知道需要填写哪些字段。

## 四、P1：核心玩具原型

### 阶段目标

做出一个 5-10 分钟的可玩玩具，验证“背包规则构筑 + 自动战斗反馈”是否成立。

### 功能范围

| 模块 | 最小实现 | 说明 |
| :--- | :--- | :--- |
| 背包网格 | 6x4 或 8x6 网格，支持拖拽、交换、旋转 | 先做稳定交互，不追求华丽 UI。 |
| 物品系统 | 道具拥有形状、标签、基础效果 | 例如断刃、聚灵符、回春丹、星核碎片。 |
| 规则系统 | 支持触发、条件、效果、代价四段式 | 先硬编码少量规则，再逐步数据化。 |
| 天命格 | 固定位置，支持“倍增”一种模式 | 只影响相邻或指定范围内的道具。 |
| 自动战斗 | 横版自动推进，角色自动攻击，敌人波次刷新 | 重点看规则触发是否清晰。 |
| 战斗日志 | 显示哪条规则触发了什么效果 | 失败时能知道是哪条链路断了。 |
| 探索节点 | 3-5 个节点组成一条短路径 | 选择奖励、战斗、事件、撤离。 |

### 内容范围

- 1 名主角叶凡。
- 1 个临时伙伴占位，可先不做完整伙伴系统。
- 12-16 件道具。
- 8-12 条规则。
- 3 种普通敌人。
- 1 个测试首领：会复制玩家最后一次触发的联动。
- 1 个测试地图：地下灵脉。

### 验收标准

- 玩家能在 1 分钟内完成一次拖拽摆放。
- 至少 3 种不同摆法能产生明显不同战斗结果。
- 战斗中能看懂天命格什么时候触发、影响了谁、带来什么结果。
- 一局失败后，玩家能从日志或结算中知道下一次该调整哪里。

## 五、P2：30 分钟 MVP

### 阶段目标

完成“序章 + 第一章前半”的正式纵向切片。这个版本要证明游戏的核心体验、叙事钩子和 30 分钟节奏能连起来。

### 地点范围

| 地点 | 功能定位 | 必备内容 |
| :--- | :--- | :--- |
| 玄离王府地窖 | 身世钩子 | 黑雪、青铜门、母亲玉印、开场短过场。 |
| 太玄宗 | 灭门事件 | 山门失守、顾玄舟遗言、黑甲追兵。 |
| 地下灵脉 | 系统教学 | 第一次背包整理、天命格觉醒、沈青萝登场。 |
| 荒古城 | 安全据点 | 商店、身份牌拍卖、任务板、基础整备。 |
| 落星谷 | 第一个完整探索区 | 星核资源、星兽首领、替身尸体线索。 |

### 系统范围

| 系统 | MVP 要求 |
| :--- | :--- |
| 背包 / 法则网格 | 8x6 网格、拖拽、旋转、相邻判定、特殊格。 |
| 天命格 | 倍增模式正式可用，有清晰冷却或次数限制。 |
| 规则收集 | 规则记录可获得、查看、装配和替换。 |
| 自动战斗 | 小队自动战斗、敌人波次、精英机制、首领阶段。 |
| 探索地图 | 节点路线、奖励选择、随机事件、撤离结算。 |
| 对话剧情 | 关键对白、短过场、剧情选择记录。 |
| 存档 | 保存背包、规则记录、剧情进度和已解锁地点。 |
| 结算 | 显示新道具、新规则、最高价值联动、下一目标。 |

### MVP 内容指标

- 30-40 件可收集道具。
- 20-30 条可装配或可发现规则。
- 8-10 个战斗关卡或探索节点。
- 2 个精英事件。
- 1 个章节首领。
- 1 名正式伙伴：沈青萝。
- 1 条完整 30 分钟主线闭环。

### 验收标准

- 新玩家 15 分钟内理解天命格的倍增效果。
- 30 分钟结束时，玩家至少记住一个人、一个地点、一个物品和一个未解问题。
- 至少两种 Build 可以击败落星谷首领。
- 剧情和玩法互相解释：玩家知道为什么“规则重组”与叶凡身世有关。

## 六、P3：第一章 Alpha

### 阶段目标

把东荒追查圈做完整，让游戏从“纵向切片”变成可以玩 2-3 小时的章节版本。

### 新增内容

| 类型 | 内容 |
| :--- | :--- |
| 地点 | 荒古城地下、剑丘、太玄宗遗址回访、后山密室。 |
| 剧情 | 三名幸存者证词、顾玄舟疑点、叶凡替身计划。 |
| 伙伴 | 沈青萝个人技能和基础羁绊。 |
| 系统 | 宗门临时据点、基础设施、规则图鉴、装备强化。 |
| 战斗 | 星兽首领重做、黑甲精英、剑丘试炼。 |
| 探索 | 旧地点回访、隐藏路线、首次区域状态变化。 |

### 技术重点

- 把 P2 中硬编码的规则迁移为数据驱动。
- 建立统一的关卡 / 事件 / 奖励配置格式。
- 加入基础调试面板，能快速切换规则、道具和战斗。
- 保存版本号，保证后续数据变更时可迁移存档。

### 验收标准

- 第一章主线可以连续游玩 2-3 小时。
- 太玄宗遗址至少发生一次可感知回访变化。
- 玩家可以形成剑意流、丹药续航流、符箓爆发流三种早期 Build。
- 宗门据点提供长期目标，但不会把游戏变成经营模拟。

## 七、P4：天衍界 Demo

### 阶段目标

完成天衍界主要体验：中央天域、南疆、西漠、北海和通天塔。这个版本应能作为公开 Demo 或较完整试玩包。

### 内容切分

| 区域 | 核心玩法 | 剧情功能 | 新规则 |
| :--- | :--- | :--- | :--- |
| 天都城 | 档案调查、通缉压力、潜行路线 | 玄离王府罪诏和年龄错位名单 | 记忆读取、身份伪装、声望分支。 |
| 南疆 | 毒雾、灵脉种子保护、蛊群压制 | 沈青萝旧师门和青木心实验 | 毒素、净化、召唤、持续效果。 |
| 西漠 | 记忆试炼、失败记录具象化 | 母亲记忆和天门代价 | 精神力判定、失败反馈转化。 |
| 北海 | 航海、天气、海兽协同 | 黑暗殿交易和天门残片争夺 | 天气标签、移动路线、撤离风险。 |
| 通天塔 | 时间切片、连续试炼 | 顾玄舟动机和跨界入口 | 百分比模式、时间规则。 |

### 系统新增

- 天命格百分比模式。
- 第二名伙伴：祁照野。
- 多区域地图和传送点。
- 阵营声望雏形：皇朝、黑市、海族。
- 伙伴支线和羁绊词条。
- 首批环境规则：毒雾、沙暴、逆流、时间切片。

### 验收标准

- 玩家能在 6-8 小时内完成天衍界主线。
- 五方灵脉最终能清晰收束成同一座大阵。
- 至少 4 个地点在主线后发生状态变化。
- 航海和通天塔不是独立小游戏，而是推动跨界路线开启。

## 八、P5：中期 Beta

### 阶段目标

进入内宇宙和外宇宙前半，验证高阶规则、阵营选择和空潮污染是否能支撑中期体验。

### 主要内容

| 模块 | 实现范围 |
| :--- | :--- |
| 四大神域 | 太虚、赤明、玄天、幽冥各 1 条核心试炼线。 |
| 阵营系统 | 临时庇护方、阵营商店、阵营支援、阵营追捕。 |
| 高阶构筑 | 高阶融合、百分比词条深化、规则冲突提示。 |
| 外宇宙入口 | 星门要塞、混沌深渊、万古坟场。 |
| 玄镜 | 作为远古规则记录体加入，提供规则触发条件改写能力。 |
| 空潮风险 | 风险值影响敌人、奖励、路线和规则稳定性。 |

### 验收标准

- 四个神域试炼玩法差异明确，不只是换皮战斗。
- 玩家选择不同庇护方，会改变前两个小时的路线、商店和首领机制。
- 空潮风险带来高收益和高不稳定性，但不会让失败显得不透明。
- 中期 Build 至少能形成 6 种可解释方向：剑意、丹道、符箓、召唤、炼化、破局。

## 九、P6：完整 Beta

### 阶段目标

补完外宇宙、混沌海、终章和多结局。此阶段重点不是继续增加系统，而是让前面所有选择被看见。

### 主要内容

| 阶段 | 地点 | 功能 |
| :--- | :--- | :--- |
| 禁地后半 | 时间裂缝、寂灭黑域、堕落花园、神魔战场等 | 补完顾玄舟、天命格和远古文明真相。 |
| 战争前线 | 混沌长城、空潮前线 | 汇总阵营、伙伴、宗门路线和污染值。 |
| 决战 | 葬神渊 | 规则失真战场，敌人针对玩家常用 Build。 |
| 终章 | 初始之地、青铜门 | 多结局判定，完成最后一次构筑。 |
| 周目 | 因果回响 | 保留图鉴和部分外观，改变关键规则关系。 |

### 结局判定维度

- 伙伴是否存活。
- 太玄宗三派是否和解。
- 空潮污染是否过高。
- 玄离王府记忆碎片是否找齐。
- 阵营声望和关键支线选择。
- 玩家常用的天命格模式和 Build 记录。

### 验收标准

- 结局不是最后一个按钮选择，而是由玩家长期行为自然汇总。
- 终局首领会改变规则，但玩家能理解变化来源。
- 至少 3 个主要结局和 1 个隐藏结局可完整触发。
- 周目内容能提供新理解，而不是单纯提高敌人数值。

---

## 十、P7：发布打磨

### 阶段目标

把完整 Beta 打磨到可发布状态。此阶段主要处理稳定性、清晰度、性能、音画和新手体验。

### 打磨清单

| 类别 | 重点 |
| :--- | :--- |
| 引导 | 前 15 分钟只教必要操作，避免一次性塞满规则术语。 |
| UI | 背包、规则链、战斗日志、结算界面必须清晰可读。 |
| 手感 | 拖拽、旋转、交换、撤销、筛选、批量整理要顺。 |
| 战斗反馈 | 规则触发、连锁成立、Boss 反制和失败原因都要可见。 |
| 性能 | 满屏特效、自动战斗和大量规则触发时保持稳定帧率。 |
| 平衡 | 每个阶段至少有 3-5 种有效 Build，避免唯一最优解。 |
| 音频 | 规则触发、联动闭合、首领破防、奖励结算有明确音效层级。 |
| 可访问性 | 字号、色盲区分、按键重绑、自动战斗速度控制。 |
| 本地化 | 文本表、规则描述、道具说明和剧情对白统一走数据。 |

## 十一、系统模块实现顺序

实现顺序建议如下，前一个模块稳定后再放大下一个模块的内容量。

| 顺序 | 模块 | 推荐目录 | 说明 |
| :---: | :--- | :--- | :--- |
| 1 | 数据加载 | `client/scripts/data/`、`client/data/` | 先定义道具、规则、敌人、关卡、剧情节点格式。 |
| 2 | 背包网格 | `client/scenes/ui/`、`client/scripts/ui/` | 拖拽、旋转、碰撞、占格、相邻关系。 |
| 3 | 规则引擎 | `client/scripts/core/` | 统一计算触发时机、条件、效果和代价。 |
| 4 | 战斗模拟 | `client/scenes/combat/`、`client/scripts/combat/` | 自动战斗、敌人波次、技能释放、战斗日志。 |
| 5 | 探索地图 | `client/scenes/explore/`、`client/scripts/explore/` | 节点路线、奖励选择、随机事件、撤离。 |
| 6 | 成长存档 | `client/scripts/save/`、`client/scripts/progression/` | 规则图鉴、剧情进度、背包状态、地点解锁。 |
| 7 | 剧情系统 | `client/scenes/story/`、`client/scripts/story/` | 对话、短过场、选择记录、剧情条件。 |
| 8 | 伙伴系统 | `client/scripts/character/` | 伙伴技能、羁绊、支线触发和战斗协同。 |

## 十三、阶段风险控制

| 风险 | 容易出现阶段 | 控制方式 |
| :--- | :--- | :--- |
| 规则太抽象，玩家看不懂 | P1-P2 | 每次触发都显示来源、对象和结果，结算复盘最高价值联动。 |
| 背包整理太累 | P1-P3 | 支持撤销、自动对齐、筛选、推荐摆放预览，但保留玩家最终选择。 |
| 战斗像纯自动播放 | P1-P4 | 加入关键节点的阵眼重排、规则切换、撤离和风险操作。 |
| 剧情和玩法割裂 | P2-P5 | 每个关键道具既是战斗组件，也是记忆和因果线索。 |
| 内容量过早膨胀 | P3-P5 | 先做少量高复用规则和区域变体，再扩展地名和剧情分支。 |
| 数值膨胀压过规则 | P3-P7 | 境界主要解锁规则容量、语法和探索权限，数值只支撑反馈。 |
| 终局选择没有重量 | P6 | 提前记录伙伴、阵营、污染、宗门和 Build 使用习惯。 |

## 十四、推荐的第一轮开发任务

第一轮不要从完整地图或剧情系统开始，建议按下面的顺序推进：

1. 建立 `Main` 主场景，能在背包、战斗、探索三个视图之间切换。
2. 实现背包网格拖拽、占格、旋转和相邻判定。
3. 实现 10 条基础规则，并能在战斗日志中输出触发结果。
4. 实现横版自动战斗灰盒：叶凡、3 种敌人、1 个精英机制。
5. 接入天命格倍增模式，让不同摆法明显改变战斗结果。
6. 做 5 个地下灵脉探索节点，形成 8-10 分钟短循环。
7. 加入一次结算，显示新规则、最高联动和下一目标。
8. 再把这套短循环扩写成太玄宗到落星谷的 30 分钟 MVP。

这一轮完成后，再决定是否扩大剧情、美术和区域。判断标准很简单：

> 只用灰盒资源时，玩家是否已经愿意反复调整背包并尝试下一条规则。
