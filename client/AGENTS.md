# 客户端开发规则

本文件适用于 `client/` 及其所有子目录。它继承仓库根目录 `AGENTS.md` 和 Agent 的默认规则；本文件只补充客户端专用约定，不覆盖上级规则。

## 1. 工程范围

- 客户端工程、客户端源码、客户端资源、客户端配置和客户端文档都必须放在 `client/` 下。
- 客户端使用 Godot 4.x；项目入口是 `project.godot`。
- 不要把客户端资源、场景或脚本放到仓库根目录、`server/`、`test/` 或 `deploy/`。
- 不要把服务端实现规则、C/C++ 服务端源码或服务端运行配置复制到客户端目录。

## 2. 目录职责

- `assets/art/`：角色、场景、特效、材质、模型和动画等美术资源。
- `assets/audio/`：音乐、音效和环境音。
- `assets/fonts/`：字体文件。
- `assets/ui/`：UI 图标和界面专用资源。
- `scenes/`：Godot 场景文件（`.tscn`）。
- `scripts/`：GDScript 脚本（`.gd`）。
- `data/`：关卡、静态表、本地化文本和其他运行时数据。
- `config/`：客户端配置、配置模板和开发环境配置。
- `docs/`：策划案、系统设计、美术规范和客户端技术文档。
- `build/`：本地构建和导出产物；该目录不提交版本库。

新增文件必须放入职责匹配的目录。不要重新创建含义不明确的 `src/`、`bin/`、`asset/` 或 `doc/` 目录。
客户端与服务端共享的离线数据工具放在仓库根级 `tools/`；客户端运行时调试工具放在 `scripts/tools/`，不要重新创建 `client/tools/`。

## 3. Godot 资源规则

- 资源引用统一使用 `res://` 相对路径，禁止使用机器相关的绝对路径。
- 移动或重命名资源后，必须检查场景、脚本、`project.godot` 和其他文本配置中的引用。
- 场景文件放在 `scenes/`，脚本文件放在 `scripts/`；场景与其主要脚本使用相同的基础名称，除非有明确理由。
- 可复用的 UI、角色和玩法组件优先制作成独立场景，避免在单个场景中堆积过多节点和逻辑。
- `.godot/` 是 Godot 导入缓存，不要手工提交或修改其中的编辑器状态文件。
- `.import` 文件由 Godot 管理；除非正在修复明确的导入问题，不要手工修改导入参数。
- 大型或可替换资源按功能继续拆分到 `assets/` 子目录，保持资源路径稳定，方便后续批量更新。

## 4. GDScript 编码规则

- 使用 Godot 4 GDScript 语法；新代码优先添加明确的类型标注。
- 文件名、函数名、变量名和信号名使用 `snake_case`；类名、场景根节点名和自定义资源类型使用 `PascalCase`；常量使用 `UPPER_SNAKE_CASE`。
- 一个脚本只负责一个清晰的节点或系统职责。UI 表现、玩法状态、网络通信和数据存储不要无边界地混在同一个脚本中。
- 节点引用优先使用稳定的节点路径和 `@onready`，避免在 `_process()` 中反复查找节点。
- 只在确实需要时使用 `_process()`；能用信号、定时器或事件驱动完成的逻辑，不要用每帧轮询替代。
- 避免硬编码数值、资源路径和用户可见文本。可调整数值放入配置或数据文件，可复用资源使用 `preload` 或集中管理。
- 不要在脚本中直接依赖场景树中脆弱的深层路径；跨场景通信优先使用明确的信号、Autoload 或受控接口。
- 每个脚本保持小而易读；复杂系统拆分为多个职责单一的脚本，并明确数据所有权和生命周期。

## 5. 场景与 UI 规则

- 场景树节点名称应表达用途，避免使用 `Node2D2`、`NewLabel` 等默认或无意义名称。
- 需要被脚本访问的节点使用稳定、可读的名称；重命名节点时同步更新脚本和动画轨道路径。
- UI 布局优先使用 Godot 的容器、锚点和主题系统，不用大量固定坐标拼接自适应界面。
- UI 文本、颜色、间距和字体等可调整内容优先放入主题、配置或本地化数据，不要散落在业务脚本中。
- 动画、音频和特效应尽量作为独立资源或独立组件维护，避免与核心玩法状态强耦合。

## 6. 数据、网络与安全

- 静态数据放在 `data/`，运行时配置放在 `config/`；不要把大量数据直接写入脚本。
- 客户端收到的网络数据必须经过格式和范围校验；客户端显示的数值不能作为服务端权威结果。
- 不在客户端保存密钥、数据库密码、服务端内部地址或其他敏感凭据。
- 网络请求、重连、超时和错误提示应集中在清晰的网络模块中；玩法脚本不要直接管理底层连接细节。
- 与服务端协议相关的变更必须同步检查协议版本、字段兼容性和错误处理，不要静默忽略未知字段或失败响应。

## 7. 变更与验证

- 修改前先确认文件所属目录和现有资源引用；优先做小范围、可回滚的变更。
- 资源替换优先保持原相对路径和文件名，减少场景引用和代码改动。
- 修改脚本后检查 Godot 编辑器错误和警告；修改场景、资源或 `project.godot` 后重新导入并检查引用。
- 条件允许时使用 Godot 无头模式打开项目并执行项目级检查；运行游戏后检查编辑器和游戏日志。
- 提交前确认没有把 `.godot/`、`build/`、临时导出文件、缓存或本地配置提交到版本库。
- 变更客户端目录职责时，先同步更新 `client/README.md` 和本文件，再移动文件。
